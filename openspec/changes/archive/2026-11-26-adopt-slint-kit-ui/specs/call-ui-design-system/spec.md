## ADDED Requirements

### Requirement: 统一组件库

call-ui 的已迁移页面 SHALL 使用 Slint Kit 组件和 `KitTheme` 令牌作为唯一视觉来源。页面代码 MUST NOT 定义自己的调色板、圆角、阴影、排版或间距体系。

#### Scenario: 迁移页面跟随共享主题
- **WHEN** 已迁移页面被渲染
- **THEN** 它的颜色、排版、间距、圆角、焦点和禁用状态来自当前 `KitTheme`
- **AND** 切换窗口主题时页面自动更新，不需要修改页面级颜色或间距值

#### Scenario: 页面内没有局部视觉常量
- **WHEN** 审查一个已迁移页面
- **THEN** 页面里没有硬编码调色板、临时圆角集合或逐控件间距刻度
- **AND** 任何视觉例外只通过一次主题字段或 Kit 组件公开的布局属性表达

### Requirement: Kit 构建与运行时接入

call-ui SHALL 使用 Slint 1.19.0 和 Slint Kit 0.9.0 构建，通过 Kit 构建助手编译 UI，并在窗口显示前为每个窗口安装一次 Kit 服务。

#### Scenario: 使用 Kit 组件干净构建
- **WHEN** 从干净检出构建 call-ui
- **THEN** `@kit` import 能解析，UI 能编译
- **AND** 生成的窗口能渲染 Kit 组件及其交互行为

#### Scenario: 所有窗口创建路径都安装 Kit 服务
- **WHEN** 应用通过任一支持的入口创建主窗口
- **THEN** Kit 服务对该窗口恰好安装一次
- **AND** 弹层定位、选择和焦点行为无需逐组件额外装配即可工作

#### Scenario: 质量门禁保持通过
- **WHEN** 一个迁移阶段完成
- **THEN** `cargo fmt --check`、`cargo clippy -- -D warnings` 和现有 call-ui 库测试通过

### Requirement: 单一窗口主题与中文支持

call-ui SHALL 为每个窗口选择一次浅色或深色模式，并把同一模式应用到所有 Kit 组件；`KitThemeContext` MUST 是唯一主题来源，不得再保留第二套 material 调色板。面向用户的中文 MUST 使用设备字体正常渲染，不能依赖只含拉丁字符的字体。

#### Scenario: 主题切换保持一致
- **WHEN** 窗口主题在浅色和深色之间切换
- **THEN** 所有 Kit 表面和控件一起切换
- **AND** 不会出现某个页面一半浅色一半深色

#### Scenario: 中文正常渲染
- **WHEN** 页面显示中文标签、按钮、对话框或输入文字
- **THEN** 所有字形正常显示，没有豆腐块或裁切
- **AND** 窗口不依赖只含拉丁字符的打包字体来覆盖中文

### Requirement: 屏幕键盘兼容

每一个接受用户输入的文本字段 MUST 使用现有的 `KbTextField`/`KeyboardCtx` 路径。聚焦这样的字段 MUST 显示屏幕键盘，上屏文字、退格和候选选择 MUST 到达该字段。非文本控件 MUST NOT 弹出屏幕键盘。

#### Scenario: 通过屏幕键盘输入文字
- **WHEN** 用户聚焦文本字段并用屏幕键盘输入
- **THEN** 键盘可见
- **AND** 上屏字符、退格和中文候选会更新当前字段
- **AND** 收起键盘后输入的文字仍保留在字段中

#### Scenario: 非文本 Kit 控件不弹键盘
- **WHEN** 用户打开下拉、菜单、滑块、开关、标签页、对话框操作或其他非文本控件
- **THEN** 屏幕键盘不出现
- **AND** 控件自身的触摸/键盘导航仍然工作

#### Scenario: 不存在静默的文本输入死路
- **WHEN** 检查 UI 中的文本输入组件
- **THEN** 没有使用未验证 OSK 适配器的 Kit 原生可编辑文本控件
- **AND** 运行中的应用里每个可编辑字段都能收到上屏文字

### Requirement: 含文本的对话框保持 OSK 兼容

包含文本字段的对话框或覆盖层 MUST 渲染在主窗口内，使屏幕键盘能够覆盖并与之交互。纯确认类对话框 MAY 使用窗口级对话框。

#### Scenario: 在对话框内编辑文字
- **WHEN** 打开一个含文本字段的对话框并聚焦该字段
- **THEN** 屏幕键盘显示在对话框内容之上
- **AND** 上屏文字到达对话框字段
- **AND** 收起键盘后对话框仍然可以关闭

#### Scenario: 无文本确认框
- **WHEN** 打开删除或挂断确认框，且其中没有文本字段
- **THEN** 不出现屏幕键盘
- **AND** 确认和取消操作仍然可以通过触摸完成

### Requirement: 分阶段、可运行的迁移

迁移 SHALL 按阶段进行，并且每个阶段完成后应用 MUST 仍可构建、启动和正常使用。material 和 Kit 组件 MAY 临时共存，但最终状态 MUST 删除 material。

#### Scenario: 阶段之间应用保持可用
- **WHEN** 设置页、应用壳或后续页面完成迁移
- **THEN** 其他页面仍能打开，原有操作仍然工作
- **AND** 应用可以在 Windows 和目标设备上启动

#### Scenario: 最终清理
- **WHEN** 迁移完成
- **THEN** 没有任何 call-ui 文件 import `material-1.1.0`
- **AND** material 下载/补丁步骤及其构建依赖被删除
- **AND** 自定义 `OptionDropDown` 组件被 Kit 下拉或菜单替代并删除

### Requirement: 迁移页面覆盖范围

设置页、应用壳和状态栏/toast 层、首页、拨号/通讯录界面、监控/通话覆盖层 SHALL 使用 Kit 组件实现视觉部分。视频渲染本身仍使用现有媒体表面。通话全屏模式 MUST 保持没有状态栏和页面壳。

#### Scenario: 设置页使用 Kit 控件
- **WHEN** 设置页显示
- **THEN** 卡片、按钮、休眠时间选择器、亮度滑块和反馈使用 Kit 组件
- **AND** 文本字段继续使用 OSK 兼容的输入框

#### Scenario: 应用壳和反馈使用 Kit 组件
- **WHEN** 应用壳显示
- **THEN** 状态栏、页面表面、错误条和 toast 使用 Kit 组件
- **AND** 原有页面切换和键盘抬升行为保持不变

#### Scenario: 通话全屏保持原布局
- **WHEN** 通话进入全屏视频模式
- **THEN** 状态栏和页面壳和以前一样隐藏
- **AND** 通话控制使用 Kit 组件覆盖在视频表面之上

### Requirement: 行为保持

UI 迁移 MUST NOT 改变 SIP 注册、ICE 通话建立、媒体收发、摄像头监控、联系人/通话记录持久化、天气、熄屏控制或键盘引擎行为。现有 UI 属性和回调 MUST 仍然连接到原来的后端操作。

#### Scenario: 迁移后后端流程仍可用
- **WHEN** 用户注册 SIP、拨打或接听电话、查看摄像头、编辑联系人、保存设置或控制熄屏
- **THEN** 调用与迁移前相同的后端操作
- **AND** 持久化值在应用重启后仍然存在

#### Scenario: 现有测试仍然有效
- **WHEN** 迁移阶段结束后运行 call-ui 库测试
- **THEN** 所有现有测试通过，不改变它们期望的后端行为

### Requirement: 翻译与无障碍

已迁移页面 SHALL 保留中英文切换，Kit 控件 MUST 保留无障碍名称、角色和焦点状态。只有图标的操作 MUST 有有意义的无障碍名称。

#### Scenario: 语言切换更新迁移页面
- **WHEN** 用户在中文和英文之间切换
- **THEN** 已迁移的标签、按钮、对话框和下拉选项无需重启即可更新
- **AND** 没有用户可见字符串留在翻译路径之外

#### Scenario: 图标操作有名称
- **WHEN** 页面包含只有图标的按钮
- **THEN** 它暴露描述操作的无障碍名称
- **AND** 键盘/触摸焦点通过 Kit 主题保持可见

### Requirement: 目标设备验证

每个迁移阶段 SHALL 在 Windows 和 1024×600 linuxkms-software 目标上验证。验证 MUST 覆盖渲染、触摸输入、弹层位置、中文字形、屏幕键盘行为和交互响应。

#### Scenario: 记录设备运行结果
- **WHEN** 一个阶段在目标设备上验证
- **THEN** 记录构建命令、后端、测试过的页面和任何渲染/性能问题
- **AND** 存在阻塞问题时该阶段不能标记完成

#### Scenario: 布局适配面板
- **WHEN** 已迁移页面在 1024×600 上显示
- **THEN** 没有控件、弹层、对话框或文字被裁出屏幕
- **AND** 下拉/菜单弹层保持在窗口边界内

#### Scenario: 软件渲染性能可接受
- **WHEN** 在 linuxkms-software 目标上使用已迁移页面
- **THEN** 页面切换、弹层打开和滚动相比迁移前没有阻塞式卡顿
- **AND** 必要的阴影或动效削减只在主题层统一应用，不逐页处理
